# GAALOPScript 完整语言参考（当前源码）

## 统计口径与结论

按“独立 statement 形态”计 13 种：空语句、普通赋值、`?` 输出赋值、`?` 输出变量、`:` 可视化赋值、`:` 可视化变量、`!` only-evaluate 赋值、宏定义、两种颜色语句、背景色、IPNS、OPNS。核心二元表达式运算符 6 个（`+ - * / ^ .`），核心一元运算符 3 个（`- ~ *`）；比较/逻辑 token 8 个但不可从 parser rule 到达。MathFunction 枚举 14 个；其中普通脚本调用先形成 `MacroCall`，经 algebra/TBA 识别，另有特殊函数 `coefficient(m, blade)`。前端实际消费 9 个 pragma（output、onlyEvaluate、in2out、segments、triangles、range、insert、return、normalize）；`unroll/count` 是遗留 pass-through 分支，不应计作当前有效指令。

## 语句

| 语法 | CFG 效果 | 支持层级/限制 | 证据 |
|---|---|---|---|
| `a = expr;` | `AssignmentNode` | E2E | grammar `:288-290`; visitor `CluVisitor.java:109-118` |
| `?a;`, `?a=expr;` | `StoreResultNode` | E2E；TBA 默认可要求至少一个 | grammar `:237-238`; visitor `:86-105`; `AlStrategy.java:47-50` |
| `:a;`, `:a=expr;` | `ExpressionStatement`/visualizer list | plugin dependent | grammar `:239-240`; visitor `:61-83` |
| `!a=expr;` | assignment + only-evaluate pragma set | semantic | grammar `:241`; visitor `:44-49`；不是 logical-not |
| `;` | 无节点 | E2E | grammar `:236` |
| `M={ statements returnExpr }` | `Macro` | E2E；只允许全局；返回可省略但调用用途受限 | grammar `:272-278`; visitor `:177-203` |
| `:Color(r,g,b,a);` / `:Red;` | `ColorNode` | visualizer/backend dependent | grammar `:245-252`; visitor `:161-165,261-264` |
| `_BGColor=Color(...);` | graph background color | visualizer dependent | grammar `:254-256`; visitor `:168-172` |
| `:IPNS` / `:OPNS` | visualization draw mode | plugin dependent；grammar 不要求分号 | grammar `:280-283` |

不支持声明关键字、类型、常量声明、多重/复合赋值、直接 blade 分量左值、return 关键字。输入变量由“使用但未赋值”推导，输出由 `?` 或 pragma 元数据产生；`$` 是合法名称字符，后续 TBA 还用 `$index` 表示分量。

## 表达式与优先级

ANTLR4 左递归替代项顺序给出优先级（高到低）：括号/一元 dual/reverse，`^`，`.`，`/`，`*`，`-`，`+`，函数与 primary。源码证据 `CluCalc.g4:292-307`，现有 `OperatorPriorityTest.java:20-24` 专门覆盖 wedge/inner 组合。

| 运算 | 脚本 | DFG/实现 | 判定 |
|---|---|---|---|
| 加减 | `a+b`, `a-b` | `Addition`, `Subtraction` | E2E |
| 几何积/标量乘 | `a*b` | `Multiplication`; TBA product table | E2E，各 algebra |
| 除 | `a/b` | `Division` → 乘 `INVERT` | E2E；零/非可逆值无语言级保护 |
| 外积 | `a^b` | `OuterProduct` | E2E |
| 内积 | `a.b` | `InnerProduct` | E2E；采用 TBA 实现的内积定义 |
| reverse | `~a` | `Reverse` | E2E，通用 grade sign |
| dual | `*a` | 函数名 `*` → 当前 algebra 的 `Dual/1` 宏 | 条件支持；宏/伪标量公式决定 |
| 负号 | `-a`, `-(expr)`, `-f(...)` | `Negation` | E2E |
| 取模 | `%` | 仅有词法 token | 不支持：表达式规则中没有入口 |
| 幂运算 | 无 | `Exponentiation` 仅存在于中间表示 | 解析器不支持 |

没有脚本级 grade extraction、grade involution、Clifford conjugation、left/right contraction、scalar/commutator product、meet/join、sandwich、exp/log of general multivectors、factorization等专用运算符。它们只能由普通运算组合、特定宏或未提供的插件实现。

## 函数与宏

任意 `name(args...)` 在 `GraphBuilder.java:411-412` 先成为 `MacroCall`。`AlStrategy` 合并当前代数宏、脚本宏与用户宏，`RecursionChecker` 禁止递归，`Inliner` 按 `(name,arity)` 解析。未知调用保留在 `graph.unknownMacros`，是否能输出取决于 backend，因此不能一概称为内置函数。

标量函数枚举：`abs acos asin atan ceil cos exp fact floor log sin sqrt tan invert`（`api/.../MathFunction.java:13-82`）。TBA 对多数函数仅支持标量分量；`invert` 主要由 division lowering 生成。`coefficient(m, blade)` 在 `Inliner.java:141-159` 特判，第二参数必须能定位 blade。

代数宏完整名称以各 `algebra/.../<id>/macros.clu` 为准。代表性集合：

- 通用约定但实现随空间变化：`Dual`；多数空间提供 `createPoint`，并非语言内置。
- CGA：`VecN3`, `createPoint`, `Dual`, `RotorN3`, `SphereN3/2`, `SphereN3/4`, `TranslatorN3`, `ExtractFirstPoint`, `ExtractSecondPoint`, `Normalize`。
- 2D/3D PGA：`createPoint`, `Dual`, `reverse`, `Normalize`, `regProd`；3dpga 另有 ideal point、line normalization、rotor/translator。
- DCGA/GAC/QGA/CCGA 含大量模型专用构造；详见 `03` 与源码 evidence index。

## pragma

`CluCalcCodeParser.java:79-173` 接受行首（trim 后）的 `#pragma` 或历史兼容 `//#pragma`：

| 名称 | 作用 | 层级 |
|---|---|---|
| `output` | 指定变量/指定 blade 输出 | algebra + backend；blade 在 `AlStrategy.java:145-190` 解析 |
| `onlyEvaluate` | 标记只求值变量 | optimizer hint |
| `in2out` | 输入到输出映射 | graph metadata |
| `segments`, `triangles` | 可视化拓扑 | visualizer/plugin |
| `range` | 变量范围 | parser metadata；格式在 `:243-257` 校验 |
| `insert` | 插入目标代码文本 | backend dependent |
| `return` | typed return definitions | backend dependent；不是 CFG return |
| `normalize` | normalize pragma metadata | plugin dependent |
| `unroll`, `count` | 遗留 pass-through | `CluCalcCodeParser.java:95-98` 仅把整行放回输入：`//#pragma` 随后作为注释跳过，`#pragma` 无 grammar 入口；没有 CFG 元数据效果 |

## 比较与控制流

lexer 声明 `|| && == != < > <= >= ! !! ->`（`CluCalc.g4:151-212`），但 expression/statement rules 不引用比较和逻辑 token；`!` 只用于 evaluate assignment，`->` 只由 pragma 文本解析。无 Boolean literal、if、else、loop、while、for、break、continue。API IR 的相关节点不可据此算语言能力。
