# 不支持的功能、歧义与潜在缺陷

## 解析器与中间表示不匹配

| 项 | 证据 | 判定 |
|---|---|---|
| if/loop/break | API 有节点，GraphBuilder 有 handler；grammar statement 无规则；negative test 打印 `no viable alternative at input 'if('` | GAALOPScript 不支持 |
| 比较/逻辑 | lexer 有 token、DFG 有类；expression 不引用 | Lexer/IR only |
| exponentiation | DFG/TBA/codegen 有节点；grammar 无 token/rule | IR only |
| modulo | lexer `%`，无 parser rule/visitor | Lexer only |
| string | lexer token，无 parser consumption | Lexer only |
| Slider/range/unroll/count | lexer tokens，grammar 无 statement | Lexer only；pragma 同名另走文本预处理 |
| `!!` | token 声明但不可达 | Lexer only |

## 语义风险

- ANTLR error listener 的行为需谨慎：负向测试可打印 recovery 错误而 Maven 测试仍通过；“产生 CFG”不一定等价于无语法错误。`CluCalcCodeParser` 对 visitor errors 的传播应继续专项审计。
- `AlStrategy.java:192-201` 捕获宏文件 parser/IO 异常后只记录日志，且 finally 直接 `reader.close()`；reader 为空存在 NPE 风险，错误可能未作为 `OptimizationException` 清晰上抛。
- 未知宏被放入 `graph.unknownMacros`，不是立即失败；不同 backend 行为可能冲突。
- macro overload 以 name+arity 区分；递归明确拒绝，嵌套非递归调用可内联。宏只能全局定义（`CluVisitor.java:177-181`）。
- 除零、sqrt 负数、log 域、null vector Normalize/inverse 没有统一语言级诊断，通常留给常量折叠、目标语言或运行时。
- 浮点 exponent 仅小写 `e` 且不接受 `e+3`；文档若声称一般科学计数法，需要更正。
- `LINE_COMMENT` 要求结尾换行，文件末尾无 newline 的注释存在词法边界风险。
- 高维 algebra 全量 `2^n` blade 生成；CCGA 17 维的组合规模很大。

## 文档与源码差异

- `GAALOPScript_Rules.md`/旧材料可能描述控制流或 IR 能力；当前 `CluCalc.g4` 是最终入口证据，普通 if/loop 不成立。
- `MathFunction` 枚举注释称全部单参数 double，但 algebra 宏中出现 `sin(half,1)`；需要视为可疑而非已支持重载。
- “dual operator”不是固定核心算子：visitor 把 `*A` 转成名为 `*` 的函数，`AlStrategy` 仅在当前 macro set 有 `Dual/1` 时别名化（`AlStrategy.java:88-91`）。
- `#pragma` 与 `//#pragma` 都支持；后者是旧式注释兼容，不应误认为普通注释具有语义。
- Wiki 把 `unroll/count` 与 pragma 体系并列的历史印象不能套到当前实现：wrapper 对二者没有 switch/CFG 写入，只作 pass-through。
- Wiki `Pragmas.md` 的 `!c = a + b`、normalize 和 return 示例缺少 grammar 必需的分号；按当前 `expression_statement` 应写成 `!c = a + b;`、`?output = ...;`、`?line = ...;`。
- Wiki `CSE.md` 声称 CLI 使用 `--opt-gcse`，但当前 `cli/Main.java` 没有该 `@Option`；应改用 `--specific de.gaalop.tba.Plugin:optGCSE=true`（需按 CLI 的 exact specific-option 语法）。

## DSL 稳定性判断

核心无控制流的代数表达式 DSL 已相当可用，且主测试链稳定；但语法存在不可达 token、IR/前端错配、插件依赖语义和弱错误传播，不能称为“完整的通用编程语言”。更准确的定位是：稳定程度中等、面向 straight-line GA symbolic code generation 的插件化 DSL。
