# GAALOPScript 源码级分析：项目架构

> 基线：本地工作树，2026-07-11。结论以源码与本轮 Maven 测试为准。

## 摘要

GAALOPScript 的实际前端不是单一 grammar，而是 `CluCalcCodeParser` 的逐行 pragma 预处理加 ANTLR4 `CluCalc.g4`。主处理链为：解析/建 CFG → 全局设置 → 可视化代码插入 → algebra definition 与宏装载/展开 → TBA 或 GAPP 优化 → codegen。根 `pom.xml` 是 Maven reactor；前端 grammar 由 `antlr4-maven-plugin` 4.9.2 生成。

```mermaid
flowchart LR
  S["GAALOPScript / .clu"] --> P["CluCalcCodeParser: pragma 预扫描"]
  P --> A["ANTLR4 CluCalc.g4"]
  A --> V["CluVisitor + GraphBuilder"]
  V --> C["API CFG/DFG"]
  C --> G["GlobalSettings"]
  G --> Z["VisualCodeInserter"]
  Z --> L["AlStrategy: definition.csv + macros.clu"]
  L --> T["TBA 或 GAPP"]
  T --> B["codegen-* 后端"]
  B --> O["C++/Java/Python/Matlab/... 输出"]
```

## 直接相关模块

| 层 | 模块/文件 | 关键符号 | 作用 |
|---|---|---|---|
| orchestration | `api/src/main/java/de/gaalop/CompilerFacade.java:55-91` | `compile` | 固定顺序调用 parser、global、visual、algebra、optimizer、backend |
| parser wrapper | `clucalc/.../CluCalcCodeParser.java:43-178` | `parseFile`, `parse` | 提取 pragma，调用 lexer/parser，补充 CFG 元数据 |
| grammar | `clucalc/src/main/antlr4/.../CluCalc.g4:7-326` | lexer/parser rules | 可从脚本文本到达的核心语法 |
| CFG builder | `clucalc/.../CluVisitor.java:44-270` | `visit*` | parse tree 到 CFG/DFG |
| builder | `clucalc/.../GraphBuilder.java:207-412` | `handleAssignment`, `handlePrint`, `processFunction` | 节点、作用域、输入/输出、宏调用 |
| IR | `api/.../cfg`, `api/.../dfg` | CFG/DFG classes | 公共中间表示；其存在不代表脚本可写 |
| algebra | `algebra/.../AlStrategy.java:45-203` | `transform` | 加载定义/宏、递归检查、内联、替换基向量 |
| macro | `algebra/.../Inliner.java:120-167` | macro dispatch | 宏参数检查、`coefficient` 特判、未知宏记录 |
| products | `tba/.../MvExpressionsBuilder.java`、`tba/.../productComputer` | expression visitors | 展开 GP/OP/IP 与标量运算 |
| optimizer | `tba/.../TBAOptStrategy.java` | `transform` | TBA 导入、传播、GCSE、Maxima 等 |
| backends | `codegen-*` | `CodeGeneratorPlugin` services | 输出目标代码；支持面并不完全相同 |
| CLI | `cli/.../Main.java:20-260` | args4j options | 默认 cga + CluCalc + algebra + TBA + C++ |

## 构建与验证

```powershell
mvn -pl cli -am -DskipTests package
mvn -pl testbenchTbaGapp -am test
```

本轮结果：两条命令均 `BUILD SUCCESS`；测试 reactor 共 188 tests，0 failure/error。测试结束时出现的 `if` 解析错误来自预期失败的 `negative/ControlFlowTest`，不能算控制流可用。

## 架构边界

- `IfThenElseNode`、`LoopNode`、`BreakNode` 与 relation/logical/exponentiation DFG 节点属于共享 IR，但 `CluCalc.g4:223-229,292-307` 没有相应脚本规则。
- `GraphBuilder.handleIfStatement/handleLoop/handleBreak` 是遗留/其他前端入口，不构成 GAALOPScript 支持证据。
- algebra 的 `macros.clu` 也是 GAALOPScript，经同一 parser 解析；`AlStrategy.java:80-109` 合并内置、脚本内和可选用户宏，然后拒绝递归并内联。
- `#include` 只在宏文件读取器 `AlStrategy.java:286-300` 中处理，普通输入文件没有同等 include 展开。
